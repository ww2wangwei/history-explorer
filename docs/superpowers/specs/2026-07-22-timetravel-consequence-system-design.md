# 「穿越历史」后果系统设计文档

日期:2026-07-22
项目:历史探索者 · TimeTravel(穿越历史)模块

## 目标

让"穿越历史"游戏**更有趣、沉浸感更强**。核心诉求覆盖:代入感(A)、选择分量(B)、
内容(C)、游戏化(D)。经讨论确定 **以"选择分量"为主轴**,通过一套**后果系统(状态值驱动)**
实现——它是 A/C/D 的挂载点:状态值给代入感提供可感载体,给评分提供依据,给新内容提供统一框架。

## 核心机制:双值对立 + 象限结局

- **双值对立**:每个剧本有两个互相拉扯的状态值,很多选择"加一个必减另一个",制造两难。
- **象限结局**:两值各分高/低(是否 ≥ 上限一半),2×2 = 4 种组合,对应 4 个结局。
  与现有"每剧本多结局(多为 3-5 个)"天然匹配。

## 三个体验层决策

- **状态呈现**:全程可见 + 实时反馈。顶部常驻两条进度条;选择后受影响值有跳动 + 数字浮动动画。
- **选项剧透**:暗示方向不暗示幅度。选项旁标方向箭头(⚔️↑ ❤️↓),知方向不知幅度,兼顾权衡与代入。
- **结局判定**:象限式(2×2)。两值高低组合匹配对应结局。
- **反馈节奏**:稍慢有仪式感(约 1.5 秒),含飘字 + 进度条动画 + 可选临界旁白,凸显决定的分量。

## 数据结构(scenarios.json 纯增量扩展)

1. 剧本级 `stats`:
```json
"stats": {
  "a": { "id": "power", "name": "兵权", "emoji": "⚔️", "init": 3, "max": 10 },
  "b": { "id": "heart", "name": "人心", "emoji": "❤️", "init": 5, "max": 10 }
}
```

2. 选项级 `effects`(方向 + 隐藏幅度,UI 只显示正负方向):
```json
{ "text": "逼宫太子", "next": "s3", "effects": { "power": 3, "heart": -2 } }
```

3. 结局级 `quadrant`(HH/HL/LH/LL):
```json
{ "id": "e1", "quadrant": "HH", "title": "贞观之治", ... }
```

判定:两值各按"是否 ≥ max/2"分高(H)/低(L),组合成象限,匹配对应 `quadrant` 的结局。

**向后兼容(关键)**:旧剧本若无 `stats`/`effects`/`quadrant`,播放器回退到现有的
`choice.next` 直连结局逻辑——未升级剧本照常能玩。支持逐个剧本升级。

## 播放器 UI 与交互

1. **顶部状态栏(常驻)**:两值各一条 mini 进度条 + emoji + 数字;高值金色辉光,危险低值红色警示。
2. **选项方向标**:选项右侧显示受影响值的方向箭头(↑绿 / ↓红),不带数字。
3. **选择后实时反馈**:数字浮动飘出(`❤️ −2` 红色上飘淡出)+ 进度条平滑增减 + 音效(增=上扬,减=低沉)→ 接现有 outcome → 下一场景。
4. **临界旁白(可选,轻量)**:某值触及极高/极低时,场景文字下加一句动态旁白(如人心≤2:"街巷间已有怨言…")。

## 安全原则

- 向后兼容:无 `stats` 剧本走原逻辑,零破坏。
- 现有 NPC 对话 / BGM / 音效 / 结局图谱全部保留不动。
- 纯前端 + 数据,不碰其他模块。
- 验证:`tsc` 零错误 + `build` 通过 + 玄武门实际玩通 ≥2 种象限结局。

- 本次不扩写新剧本内容(C)。
- 本次只升级玄武门一个剧本,其余留阶段 2。
