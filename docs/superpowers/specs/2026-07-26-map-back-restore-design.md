# 地图 Back 完整恢复来源页面设计

日期：2026-07-26

## 目标

用户从首页事件、战争、文化或地理详情进入地图定位后，点击地图信息卡的 Back，必须回到进入地图前的原栏目，并恢复原来打开的详情、弹窗和选中项。

## 当前机制

- `useJumpToMap` 根据跳转参数生成 `pendingReopen` payload。
- 地图卡片通过 `reopenKind` 映射 `history:go-*` 事件。
- `Layout` 接收事件并切换主栏目。
- Dashboard、Wars、Cultures 等来源组件在挂载时消费 `pendingReopen` 并恢复局部 UI。

当前缺陷是 Back 流程只保证栏目切换，来源信息与栏目恢复之间缺少统一、可验证的契约，部分入口会退回默认页面或无法恢复详情。

## 设计

### 1. 来源状态契约

继续使用 `pendingReopen` 作为唯一来源状态。每个地图跳转入口必须写入：

- `kind`：来源类型；
- 来源实体 ID；
- 恢复详情所需的最小附加状态（如事件年份、战争节点索引）。

不保存完整组件快照，避免与页面内部实现耦合。

### 2. Back 执行顺序

地图信息卡点击 Back 时：

1. 根据 `reopenKind` 查找原栏目事件；
2. 保留 `pendingReopen`，不提前消费；
3. 派发栏目切换事件；
4. 清除地图卡片及 `mapFocusTarget`；
5. 来源组件挂载后读取并消费 `pendingReopen`，恢复原详情；
6. 恢复完成后清除 `pendingReopen`。

无有效来源时回退到学习引导主页。

### 3. 来源覆盖

- `quickEvent`：首页快速学习弹窗及事件；
- `event`：首页事件详情；
- `war`：战争详情；
- `majorWar`：大战详情；
- `majorWarNode`：大战节点详情；
- `cultureEvent`：文化事件详情；
- `geoFeature`：地理特征详情；
- `territory`：疆域详情。

### 4. 组件边界

- `useJumpToMap`：生成来源 payload；
- `reopenRoutes.ts`：维护来源类型到栏目事件的映射；
- `TMapTest`：只负责触发 Back，不解释来源详情；
- `Layout`：只负责切换主栏目；
- 各来源组件：只负责消费自己的 payload 并恢复局部 UI。

## 错误处理

- `pendingReopen` 缺失或类型未知：返回首页；
- 来源实体已不存在：打开对应栏目默认页，并清除 payload；
- 重复点击 Back：第一次触发后立即关闭地图卡片，防止重复派发。

## 测试

1. 首页快速事件 → 地图 → Back：恢复快速学习弹窗与事件；
2. 首页事件详情 → 地图 → Back：恢复事件详情；
3. 战争详情/大战节点 → 地图 → Back：恢复相同战争及节点；
4. 文化事件 → 地图 → Back：恢复相同文化事件；
5. 地理特征/疆域 → 地图 → Back：恢复相同详情；
6. 无来源信息的地图卡片 Back：安全回退首页；
7. 每次恢复后 `pendingReopen` 被清除，不会在后续导航中重复弹出。

## 范围

本次只修复地图信息卡 Back 的恢复语义，不引入浏览器历史栈，不重构全局路由。
